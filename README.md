# Ghazipur Landfill Fire & Contamination Shield

**IBM Z Datathon 2026 — Theme 1: Real-time AI for critical decisions**

A live decision-support system for Delhi's Ghazipur landfill that **predicts fires**,
**decides what to dig and where to send it**, and **generates the warnings and work orders** —
on one screen. Built as a **Predict → Decide → Generate** pipeline designed to run on
**IBM LinuxONE (s390x)**.

> ⚠️ **Data honesty:** the landfill sensor stream (per-zone surface temperature & methane)
> is **SIMULATED** — those feeds don't exist publicly. Weather can be **live** (Open-Meteo).
> Every real-world figure is sourced in [`docs/SOURCES.md`](docs/SOURCES.md); anything
> unsourced is marked UNVERIFIED.

## The problem

Ghazipur is an ~8.2 million tonne, 65 m-high waste mountain (operating since 1984) that
repeatedly catches fire, choking nearby homes and schools with toxic smoke. Crews are
biomining it down (target ~12,000 t/day) but must decide **which zone to dig first** and
**where to send** the excavated waste without overloading any plant.

## The solution

| Stage | Component | What it does | Technique |
|---|---|---|---|
| **Predict** | **Model A** | Predicts 24h fire risk for each of 12 zones | RandomForest (**ML**) |
| **Decide** | **Model B** | Ranks zones (dig riskiest first) + routes waste fractions to plants by capacity, minimising transport | networkx min-cost flow (**optimisation**, not ML) |
| **Generate** | **Model C** | Writes a downwind resident smoke/health alert + a daily crew excavation & truck-dispatch plan | templates offline / optional **IBM Granite** LLM |

See the pipeline diagram in [`docs/flowchart.md`](docs/flowchart.md).

## Architecture

- **Model A** (`notebooks/01_fire_model.ipynb` → `models/fire_model.joblib`) trains on
  `data/landfill_sensors.csv`. The fire label is grounded in landfill-fire science: a
  McArthur fire-weather term, an ~80 °C self-heating/smoulder threshold, and a 50,000 ppm
  (5% LEL) methane term (see `docs/SOURCES.md`).
- **Model B** (`models/optimiser.py`) consumes per-zone risk + `data/plants.csv` and solves
  a capacity-constrained min-cost flow; returns JSON (dig order, routing, utilisation,
  unallocated tonnes). Generalises to other cities by adding graph nodes.
- **Model C** (`models/genai.py`) turns Model A + B output into plain-English text.
- **Dashboard** (`dashboard/app.py` + Leaflet) shows a live risk map, routing lines, panels,
  a **heatwave slider** (stress test) and a **live-weather toggle** (`dashboard/weather.py`).

## Dashboard features

- 12 zones coloured & sized by fire risk; plants as markers; routing lines sized by tonnage.
- Simulated live stream (advances 1 hour every 3 s).
- **Heatwave slider (0–100%)** — raises temperature / lowers humidity so risk, routes and
  alerts change live.
- **Live weather toggle** — pulls real current Ghazipur weather from Open-Meteo.
- Panels: dig order, routing table, resident alert, crew plan. "Simulated sensor data" badge.

## How to run

```bash
pip install -r requirements.txt
python dashboard/app.py          # -> http://localhost:5000
```
Retrain the model (optional): `python data/generate_data.py` then execute
`notebooks/01_fire_model.ipynb`. Container & IBM LinuxONE (s390x) instructions:
[`docs/setup_linuxone.md`](docs/setup_linuxone.md).

## Tech stack

Python · scikit-learn (Model A) · networkx (Model B) · Flask + Leaflet.js (dashboard) ·
pandas / numpy · joblib · Open-Meteo (live weather) · optional IBM Granite (Model C) ·
packaged for podman/docker on IBM LinuxONE. CPU-only, no GPU, no secrets.
